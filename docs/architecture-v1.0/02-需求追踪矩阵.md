## 3. MVP 范围纪律

- R01—R10 为平台能力基础，其中部分在 MVP 使用简化版本验证。
- R14、R17 作为**业务演示样例**，不代表已经覆盖 R17 的所有深度分析内容。
- R11—R13、R15—R16 以及 R17 的扩展分析留给后续专业领域迭代；在菜单、README、演示中不可宣称已交付。
- 数据服务建议属于“建议/草稿”，非自动发布；血缘推断属于“辅助推断”，非事实确认。

## 4. 可审计回答验收示例

**输入**：分析当前表最近七天的质量变化。  
**最低合格输出**：回答包含标准对象 ID、实际统计区间、指标及单位、数据源引用句柄、可用数据量、结论/推测边界。  
**不足情况**：缺少 3 天统计数据时返回 `partial` 并明确缺口，不得生成连续七天完整趋势。  
**权限情况**：业务接口拒绝字段时，模型不能展示该字段或使用旧会话缓存绕过授权。  
**追溯情况**：点击 Evidence 引用由服务端重新鉴权后解析，不能生成无需权限的直链。

## 5. 后续新增需求的维护规则

新业务需求需补充 `R18+`；新增架构约束补充 `A10+`；改变数据契约必须加契约版本并更新 M5 回归测试。不得将尚未实现的功能写成 `done`。
