# 03 · 工程目录、依赖规则与配置约定

## 1. Monorepo 总体目录（目标形态）

```text
ai-assistant/
├── AGENTS.md                         # 从文档包复制的 Codex 常驻规则
├── apps/
│   ├── agent-server/                 # Node API、启动装配、插件发现、Session/Run
│   ├── assistant-web/                # React 独立 Web、聊天与管理菜单
│   ├── assistant-embed/              # iframe 内运行的独立入口
│   └── demo-host/                    # React/原生 JS/iframe 测试宿主
├── packages/
│   ├── contracts/                    # 前后端事件/SDK/API Schema
│   ├── agent-runtime/                # Deep Agents Factory、Runner、Event Bridge
│   ├── plugin-sdk/                   # definePlugin / implementCapability
│   ├── plugin-runtime/               # Manifest Loader、Lifecycle、Local/HTTP Driver
│   ├── assistant-ui/                 # React + Ant Design X 共享 ChatWorkspace
│   ├── assistant-sdk/                # React / JS 对外集成 API
│   ├── iframe-bridge/                # Host / iframe 双端 postMessage 协议
│   └── assistant-transport/          # Session/Run HTTP + SSE Client
├── core/
│   ├── context/                      # Raw/Normalized/Verified Context、Snapshot
│   ├── capability/                   # Catalog、Registry、Dispatcher、Schema
│   ├── policy/                       # 授权接口、风险分类与强制校验
│   ├── evidence/                     # 来源引用/检索/二次授权
│   └── result/                       # CapabilityResult / ViewModel
├── platform/
│   ├── model-registry/               # 模型配置/凭证引用
│   ├── session-service/              # 会话元数据/Thread/Run
│   ├── agent-registry/               # Agent 配置/模型/工具和技能绑定
│   ├── plugin-registry/              # 插件安装元数据与状态
│   └── system-settings/             # 当前实例的基础配置
├── adapters/                         # 插件源码，部署时只安装所需产物
│   ├── demo-product-a/
│   └── demo-product-b/
├── domains/                          # 专业 Agent/Prompt/Schema；首版数据质量样例
├── skills/                           # SKILL.md、参考规则；由 Backend 映射
├── deployments/
│   ├── product-a/
│   └── product-b/
├── tests/                             # 集成/契约/E2E/安全测试
└── pnpm-workspace.yaml
```

这是目标目录；M0 可先创建有内容的最小 Workspace，后续逐阶段补齐。不要生成数十个空壳包充数。

## 2. 代码依赖约束

1. `core/*` 不导入 `deepagents`，不导入 `adapters/*`，不导入 React UI；保持业务契约中立。
2. `packages/plugin-sdk` 只导出插件开发 API 与 Core 公共类型，不依赖 Harness。
3. `adapters/*` 依赖 `plugin-sdk` 和公共契约；不得直接调用 `createDeepAgent`。
4. `packages/plugin-runtime` 实现 Loader/Drivers，消费 Plugin SDK 类型；不决定 Agent 如何推理。
5. `packages/agent-runtime` 可以依赖 `deepagents` 和 Core/Platform 接口，但不直接依赖具体产品 API。
6. `apps/agent-server` 是 Composition Root，负责注入 Registry、Loader、DB、Logger 等实现；避免业务代码全局单例污染测试。
7. `packages/assistant-ui` 只接收标准消息和 ViewModel，不接触模型密钥、不依赖插件实现。
8. `assistant-web`、`assistant-embed` 通过 UI/SDK/Transport 复用聊天组件；各自 UI Shell 可不同。

## 3. Workspace 与构建

- Node.js LTS、pnpm、TypeScript `strict`；版本在 M0 按官方兼容要求明确写入 `engines`、`packageManager`、锁文件。
- 建议 ESLint、Prettier、Vitest、构建器；Web 使用 Vite；不预设固定版本号或不兼容的 React/Ant Design 组合。
- 统一路径别名只能作用在包源码构建边界内；跨包使用显式 package exports，避免访问其他包 `src/internal`。
- 每个实际 Workspace Package 独立提供 `typecheck`、`test`、`build`（适用时）；根脚本统一执行。

示意：

```yaml
packages:
  - 'apps/*'
  - 'packages/*'
  - 'core/*'
  - 'platform/*'
  - 'adapters/*'
  - 'domains/*'
```

`skills/` 保存静态技能资源，不需要作为 pnpm package。

## 4. 配置分层

| 类型 | 示例 | 存放/责任 |
|---|---|---|
| 构建常量 | App Version、协议版本 | 构建与版本管理 |
| 实例启动配置 | `PLUGIN_DIR`, `DATABASE_URL`, `ALLOWED_IFRAME_ORIGINS` | 环境/配置服务 |
| 插件配置 | API 基地址、超时、凭证引用 | 当前部署的受控配置存储 |
| 模型配置 | Provider、模型 ID、启停、能力 | Model Registry；密钥存 Secret Store |
| 用户/会话上下文 | 用户、当前对象、线程、权限 | 每次请求可信服务端解析 |

严禁提交 `.env` 实密钥，禁止把模型 Token/产品长期 Token 写入 `plugin.json`、浏览器 Bundle 或 Git。

## 5. 独立部署模型

- 开发源码可同时存在 A 和 B 插件；A 实例的发布包只安装 A 所需插件，B 实例只安装 B 所需插件；**启动按安装目录扫描**。
- 每套实例独立 `DATABASE_URL`、Checkpoint Store、模型配置与 Secret；不建跨部署 Session Federation。
- 插件安装产物优先放 `/opt/ai-assistant/plugins` 之类可配置目录；只扫描已审核构建包，不执行任意上传 JS。
- 进程启动报告 `pluginId`、`version`、`capabilityIds`、健康状态和冲突，且不打印凭证。

## 6. 交付脚本与命令规范

M0 完成后应有 `pnpm install --frozen-lockfile`、`pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm build`（若有）统一命令。后续阶段增加 `test:contract`、`test:integration`、`test:e2e`。若必须依赖联网或真实模型，测试需要有明确的跳过标识与 Mock 替代；禁止用“无模型密钥”掩盖纯逻辑测试失败。

## 7. README/变更记录

每个阶段提交应同步更新仓库 `README.md`、`docs/implementation-status.md`（创建于 M0）与 `docs/decisions.md`（遇到设计变更时）。实施状态必须区分 `未开始 / 开发中 / 已验证 / 阻塞`。
