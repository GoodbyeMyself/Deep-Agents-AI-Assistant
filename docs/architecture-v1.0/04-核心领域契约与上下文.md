# 04 · Core 五大模块与标准业务契约

> Core 契约由平台自主实现。**下述 TypeScript 是接口设计稿，不能误当成已有 npm API**。M1/M2 需要写出真实 Zod Schema、类型、单元测试与契约版本。

## 1. 五大模块分工

| Core | 拥有什么 | 禁止承担 |
|---|---|---|
| `context` | 原始页面信息、标准业务语义、上下文快照接口 | 信任浏览器自报权限/重写 LangGraph 状态 |
| `capability` | 标准能力 Catalog、Provider Binding、Registry、Dispatcher、Executor | 自建 Agent Loop / 绑定 A/B 产品名字 |
| `policy` | 标准能力风险和授权请求/结果接口 | 替代原业务行列权限校验 |
| `evidence` | 可信来源/统计口径/引用句柄/解析接口 | 让模型自行声明已验证事实 |
| `result` | `CapabilityResult`、标准错误、ViewModel | React JSX / 原始插件数据结构 |

## 2. Context 三层模型

**RawHostContext**：宿主 SDK 上报页面路由、对象原始标识及业务模块，可被伪造，**不得作为身份或权限依据**。  
**NormalizedContext**：经当前插件的 `contextAdapter` 标准化后供 Agent 理解的 `{user, permissions, page, object, business}`；其中身份和权限字段仅从服务端授权数据填充。  
**TrustedExecutionContext**：服务端维护用户、租户、会话、授权范围、产品连接与凭证引用；禁止完整复制进 Prompt、Tool 参数或客户端。

```ts
export type WebMode = 'assistant' | 'standalone';
export type DomainObjectType = 'data_table' | 'data_source' | 'dataset' | 'metric' | 'service' | 'task' | 'document' | string;

export interface RawHostContext {
  page?: { route?: string; title?: string; type?: string };
  object?: { type?: string; rawId?: string; name?: string };
  business?: { domain?: string; module?: string };
  metadata?: Record<string, unknown>; // 严格白名单，限制大小
}
export interface NormalizedContext {
  user: { id: string; displayName?: string }; // 仅后端写入
  permissions: { scopes: string[] };            // 仅后端写入
  page?: { type: string; route?: string; title?: string };
  object?: { type: DomainObjectType; id: string; name?: string };
  business?: { domain: string; module?: string };
}
export interface ContextSnapshot {
  id: string; version: number; mode: WebMode;
  capturedAt: string; context: NormalizedContext;
}
export interface TrustedExecutionContext {
  id: string; sessionId: string; runId: string; traceId: string;
  authenticatedUserId: string; tenantId?: string;
  contextSnapshotId: string; authorizationRef: string;
}
```

**时序规则**：每次 Run 固定 `contextSnapshotId`；页面切换仅更新下一次请求。Tool 执行仍须实时做权限检查，Snapshot 不能作为永久授权票据。Standalone 模式中 `page`/`object` 可为空；用户通过业务选择器建立对象上下文。

## 3. Capability Contract / Provider / Instance

**Catalog** 注册标准业务语义和输入输出 Schema；**Provider** 是插件提供的一个执行实现；**Binding** 是当前部署选中的可用 Provider；Tool Factory 将标准契约映射为模型可调用工具。插件版本与能力契约版本是两个概念。

```ts
import { z } from 'zod';
export interface CapabilityContract<I extends z.ZodType, O extends z.ZodType> {
  id: string;                       // data_quality.get_trend
  version: string;                  // 建议 V1 使用 1.0.0
  description: string;
  inputSchema: I; outputSchema: O;
  requiredPermission: string;
  riskLevel: 'read' | 'write' | 'high';
}
export interface CapabilityBinding {
  capabilityId: string; contractVersion: string;
  pluginId: string; pluginVersion: string;
  driver: 'local' | 'http' | 'mcp';
  status: 'registered' | 'available' | 'degraded' | 'disabled';
}
```

**重名与版本**：同一 ID+同一契约版本如果存在多个 Provider，启动失败或由显式绑定规则选择；不能按加载顺序覆盖。不同主要版本并存须清楚限定支持范围。不能无声转换具有不同业务含义的字段。

## 4. 标准返回结果与错误语义

```ts
export type CapabilityStatus = 'success' | 'partial' | 'error';
export type CapabilityErrorCode =
  | 'UNAUTHORIZED' | 'FORBIDDEN' | 'INVALID_INPUT' | 'UNSUPPORTED'
  | 'UPSTREAM_TIMEOUT' | 'UPSTREAM_ERROR' | 'SCHEMA_MISMATCH'
  | 'INSUFFICIENT_DATA' | 'PROVIDER_UNAVAILABLE';
export interface CapabilityResult<T> {
  status: CapabilityStatus;
  data: T | null;
  evidence: Evidence[];
  dataScope?: { start?: string; end?: string; filters?: Record<string, unknown>; timezone?: string };
  warnings: Array<{ code: string; message: string }>;
  error?: { code: CapabilityErrorCode; message: string; retryable: boolean };
}
```

基本规则：
- `success` = 业务数据满足契约及分析范围，证据按要求存在。
- `partial` = 数据缺口、口径差异、部分数据授权/上游能力不足；必须附明确 warnings。
- `error` = 授权失败、上游故障、Schema 不匹配等；不把异常当作空数据/零值。
- 遵循 `outputSchema.parse`；不合格结果不得向模型呈现为有效数据。
- **对模型返回**只限脱敏、安全的结果摘要和 Evidence 引用句柄，不返回内部业务凭证及敏感完整原始响应。

## 5. 首批两项标准能力

### 5.1 `data_map.search_objects@1.0.0`

**输入：** `keyword: string`、`objectTypes?: string[]`、`limit?: number (1..50)`、可选过滤对象范围。  
**输出：** `objects[]`，每项有 `type`、`id`、`name`、可选 `description`、`sourceRef`；可选分页 `nextCursor`。  
**权限：** 继承业务系统检索范围，不可发现用户无权见的对象元数据。  
**MVP** 使用模拟系统、库、表、字段对象，后续增加指标/接口/任务/应用。

### 5.2 `data_quality.get_trend@1.0.0`

**输入：** `{ tableId: string; startTime: string; endTime: string }`，日期区间与大小限制由 Schema/业务服务执行。  
**输出：** `{ tableId, metric: 'quality_score', unit: 'percent', aggregation: 'daily', timezone, points: [{time, value}], missingDates?: string[] }`；同时附数据范围、口径、统计时区、证据。  
**语义：** 质量评分必须定义取值范围和聚合方式；B 产品如只有按月指标，不能伪造每日 points；返回 `partial` 或 `UNSUPPORTED`。

示意 Zod 契约：

```ts
import { z } from 'zod';
export const QualityTrendInput = z.object({
  tableId: z.string().min(1),
  startTime: z.string().datetime({ offset: true }),
  endTime: z.string().datetime({ offset: true }),
});
export const QualityTrendData = z.object({
  tableId: z.string(), metric: z.literal('quality_score'),
  unit: z.literal('percent'), aggregation: z.literal('daily'),
  timezone: z.string(),
  points: z.array(z.object({time: z.string(), value: z.number().min(0).max(100)})),
  missingDates: z.array(z.string()).optional(),
});
```

**注意：** 时间跨区间、数据单位、缺失天数、统计口径的比较应在执行器或领域服务中校验；不要靠 LLM 判断字段类型与百分比转换。

## 6. Evidence 与可验证事实

```ts
export interface Evidence {
  id: string;
  source: { type: 'table' | 'dataset' | 'metric' | 'record' | 'task' | 'document' | 'service'; id: string; title?: string };
  collectedAt: string;
  dataScope?: { from?: string; to?: string; filters?: Record<string,unknown> };
  methodology?: string;
  referenceId: string;  // 服务端内部引用句柄，不是公开访问 URL
}
```

证据生成主体优先是**受控 Capability Executor / 原平台**；模型不能凭字符串自行添加 `verified=true`。证据展示需重新校验访问权限。结论分类：`observed`（数据实证）、`inferred`（证据支持的推断）、`unknown`（资料不足）。

## 7. 结果视图协议

通过 `core/result` 定义 `AssistantView` 版本与 TypeScript 判别联合类型，如 `text`、`metric`、`table`、`chart.line`、`references`。每类有受控 Schema 和 EvidenceRefs；Renderer 按 `viewType` 查受信任的 UI 实现，绝不允许插件发送任意 React 代码或 HTML 进行执行。

## 8. 必须提供的契约测试

- 两个模拟插件实现同一 Capability；相同测试向量在标准数据意义上等价。
- 参数非法、对象不存在、越权、缺失三天、上游超时、单位冲突、部分失败有稳定错误码。
- 不得暴露内部字段/凭证；证据引用再次授权。
- `contextSnapshotId` 与 Tool Run 绑定；模拟前端页面切换不影响已开始的查询。
