# M0 · 工程初始化与 Deep Agents 框架验证

> 依赖：无；预计输出：可启动的 Node/TypeScript POC + pnpm Workspace + 框架兼容性记录。  
> 允许改动：根配置、`apps/agent-server`、`packages/agent-runtime`（最小）、`tests/`、`docs/`；暂不做插件平台/React 业务页面。

## 1. 目标与不做项

验证在当前开发环境实际安装的 **Deep Agents TypeScript SDK** 能实现真实工具调用、Skills、Subagent、Streaming、Checkpoint，并锁定包和示例。重点是消除官方版本 API 与之前设计示例之间的差异。**本阶段不能通过自己写 Agent Loop 来掩盖官方兼容问题。**

不做：企业权限平台、完整会话管理、数据治理业务、产品 A/B 插件、Ant Design X UI。

## 2. 启动前检查

1. 记录 Node/pnpm/OS、Git 状态；不要覆盖已有用户代码。
2. 检查官方文档和 `deepagents` 当前安装版本类型，明确 Node ESM 与依赖兼容；选择稳定版本写入锁文件。
3. 读取 `00-README`、`01`、`03`、`06`、`16`、`AGENTS.md`，列出实施计划。
4. 不向仓库提交真实模型密钥；提供 `.env.example` 和故障提示。

## 3. 工作包

### M0-T01：根工程

- 创建 `pnpm-workspace.yaml`、`package.json`、`tsconfig.base.json`、ESLint/Prettier/Vitest 配置。
- 创建 `apps/agent-server`、`packages/agent-runtime` 的可运行最小 workspace；后续目录以空 README 或按需生成。
- 根脚本：`lint`, `typecheck`, `test`, `build`；配置 CI 最小 job。

### M0-T02：Deep Agents 最小 Agent

- 引入 `deepagents`、`langchain`、`@langchain/core`、`zod` 与指定模型 Provider SDK。
- 使用官方 `createDeepAgent` + `tool()` 实际执行可观察的 `ping` 工具。
- 无模型 key 的测试：用 Mock ChatModel/Stub 进行纯集成契约检查；有 key 时可以执行带环境标识的真实模型烟测。

### M0-T03：Skills、Subagents、Backend

- 加载一个只读 SKILL.md，明确实际文件路径与 Backend 虚拟路径映射。
- 建立一个专用只读子智能体，仅有其自己的工具；验证委派事件/输出。
- Checkpointer 至少验证同一 thread_id 的后续请求可访问对话上下文；真正重启持久化留给 M2。
- 核验 `contextSchema`/Run Context 如何传递，确认工具可访问的可信引用方法。

### M0-T04：Streaming 事件观察

- 打印真实的 `stream`/`updates`/`messages` 数据结构，包含 Tool Call / Subagent event；保存不含秘密的 Fixture。
- 尝试 `subgraphs: true` 并确认 event namespace 形状；不要基于猜测写事件解析器。
- 写 `docs/deepagents-compatibility.md`：版本、实际可用参数、TypeScript 类型、测试日志摘录、已知差异/降级策略。

文件名是推荐，不强制与已有工程冲突。

## 5. 测试与验收

- `pnpm install --frozen-lockfile`、`pnpm typecheck`、`pnpm lint`、`pnpm test`、`pnpm build` 均通过。
- 测试可证明工具**真的**被调用，而不是模型单纯回答 `pong`。
- Skills 被 Backend 成功读取；Subagent 确实只接收限定工具。
- 同 Thread 的上下文连续性可验证；Stream Fixture 保存事件实际结构。
- `docs/deepagents-compatibility.md` 说明当前版本默认规划策略与具体启用方式；未证实的不写死。
- 不依赖真实模型密钥即可运行大部分 CI 测试，真实烟测另行标记。

## 6. 阶段退出与阻断条件

若 TypeScript SDK 关键能力（contextSchema、Skills、Subagents、Streaming、Checkpointer）与需求不兼容，**先提交阻断清单和最小复现**；不要重写 Harness。需要架构决策才能换 Python 或变更插件机制。

## 7. 给 Codex 的阶段指令

> 阅读 `AGENTS.md` 和 `10-M0-工程初始化与框架验证.md`，先检查已有仓库并核对安装的官方 Deep Agents TypeScript 依赖和 API；按 M0-T01~T04 实现。不要编写 Plugin Runtime、产品适配器或 UI。补充工具调用/Skills/Subagent/Streaming/Thread 的测试，执行所有根脚本并更新兼容性文档。最终报告变更文件、实际运行命令、测试结果和未验证事项。完成后停止，等待 M1 任务。
