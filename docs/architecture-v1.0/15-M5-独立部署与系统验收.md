# M5 · 产品 A/B 两套独立部署与 V1.0 整体验收

> 依赖：M0—M4 基础验收通过；应具备两个模拟或真实业务 Adapter。  
> 允许改动：`deployments`、容器配置、CI、测试、文档，以及为修复验收缺陷所必需的具体模块；不得未经审核扩大架构范围。

## 1. 成功目标

同一套代码产物经不同插件安装与部署配置，分别形成 A/B 两套**完全独立**实例；两个实例对用户呈现统一的业务能力与交互体验，但会话、模型配置、业务数据、身份和数据库均不共享。

## 2. 部署清单

| 部署元素 | A 实例 | B 实例 |
|---|---|---|
| 镜像/构建产物 | 同一版本 | 同一版本 |
| 插件安装目录 | 仅已批准 A 插件 | 仅已批准 B 插件 |
| 业务 API | A 的 API 地址与凭证 | B 的 API 地址与凭证 |
| Checkpointer | A 独立存储 | B 独立存储 |
| Session/Run/Model DB | A 独立存储 | B 独立存储 |
| Agent/Skills | 共用标准配置包 | 共用标准配置包 |
| 前端 UI | 同一 Chat Core、可配置主题 | 同一 Chat Core、可配置主题 |
| 插件 Tool 名称 | 相同标准 Capability | 相同标准 Capability |

## 3. 工作包

### M5-T01：打包与启动

- 可靠的 `Dockerfile`/容器编排 Demo（如选择 Docker Compose）；明确启动顺序：DB/Checkpointer → 插件扫描 → Catalog/Registry → Agent Server → UI。
- 采用生产环境变量或 Secret 注入；配置缺失时阻断启动并打印脱敏错误。
- 输出 `GET /healthz`（进程）与 `GET /readyz`（数据库、可用模型、必需插件）；不泄露敏感信息。

### M5-T02：独立部署测试

- 用 A 安装包启动 instance-a，B 安装包启动 instance-b。
- 对同一个标准工具请求分别取得各自业务系统结果；测试 API 原始字段不同，标准结果 Schema 相同。
- A 用户的 Session ID 在 B 实例不可读取；B 的业务 API 与 Session DB 不与 A 共享。
- 测试两个实例管理页面分别维护模型、插件状态和历史会话。

### M5-T03：完整端到端业务场景

1. 在 A 的 React/iframe 宿主打开当前数据表，提问“最近七天质量变化”。
2. 观察 ContextSnapshot；Deep Agents 实际调用 `data_quality_get_trend`。
3. Tool Executor 使用当前用户权限；业务 API 返回真实模拟/联调数据；标准化结果携带统计口径和证据。
4. 前端呈现文字、趋势图、缺失警告和依据；刷新后仍能访问自己的会话。
5. 在 B 独立部署环境执行同一场景，Agent Core 和 UI 不作任何产品分支改动。
6. 模拟 B 不支持某种统计口径，要求明确 `partial/UNSUPPORTED`，不能伪造。

### M5-T04：非功能质量

- 并发和延迟：建立测试环境基线，关注 TTFT、流式中断率、API 延迟、插件错误率、内存增长；真实 SLA 需用户/产品另行定义，不凭空承诺。
- 审计：能查询一次回答关联的 user/session/run/model/capability/plugin/dataScope/evidence/error。
- 安全：重放 08 文档中的恶意场景与跨用户访问测试。
- 升级：插件同契约版本升级不影响 Agent/前端，契约主版本变更必须产生明确兼容性诊断。

## 4. 必需交付物

- A/B 两套可启动的部署示例（可使用模拟业务 API），`deployments/README.md`、环境变量模板。
- M0—M5 自动化测试报告与失败项归档。
- 插件开发手册、SDK 接入手册、管理员使用说明、运维故障排查说明。
- `docs/implementation-status.md` 完整显示实际完成状态；未实现模块列待办。
- 一条真实可重复演示的 Run Trace（可脱敏、不能泄漏密钥）。

## 5. 发布门禁（DoD）

- 基础 lint/typecheck/test/build 全通过；关键契约/权限/E2E 测试通过。
- 无裸露密钥，无跨用户读写，无未审核插件执行。
- `AssistantWeb` 与 `AssistantEmbed` 都能在 A、B 独立环境运行；会话数据不互通。
- 新增 C 产品所需工作被清晰限制为**实现符合标准契约的新插件 + 安装部署**（若 C 缺少能力时可用性状态明确），而不是修改 Agent 基础源码。
- 满足 V1.0 MVP 范围；对完整业务需求覆盖仅声明已实现的具体条目，不虚报 R11—R17 的全部高级领域功能。

## 6. Codex 阶段指令

> 阅读全部基线文档，重点读 01、02、08、09、15、16 和 AGENTS.md。用同一源码版本创建 A/B 两套隔离的构建/部署配置，只在各自实例安装本产品插件，运行完整系统和安全测试。输出配置清单、部署/回滚步骤、Trace 示例、验收报告以及尚未覆盖的 R 需求。未经同意不要引入集中式跨产品会话系统或插件热加载。完成后产出 v1.0 release checklist。
