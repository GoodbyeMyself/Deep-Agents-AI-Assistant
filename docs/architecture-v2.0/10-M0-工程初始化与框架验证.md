# M0 · 重新初始化与 Deep Agents 公共能力验证（V2.0）

> **本 M0 可从头重做，不延续旧 M0 的技术决策或验收结果。** 若仓库已有代码，先检查 Git 状态并保护用户数据；只在用户授权范围内清理或覆盖。  
> 输入：`AGENTS.md`、`00`、`01`、`03`、`04`、`06`、`16`、`18`。  
> 输出：一个能真实调用 Tool 的 Deep Agent + 版本锁 + 可靠测试 + 兼容性报告。  
> 禁止：完整 Plugin Loader、管理后台、复制 Agent Loop。

## 目标

- 确定可工作的官方 Deep Agents TypeScript SDK 版本；验证 Tool、Streaming、Runtime Context、Skills、Subagents、Checkpointer 的公开扩展点。
- 建立干净可维护的 Node/pnpm/TypeScript 仓库；保留 `core/capability` 公共契约的**最小示例**用于 M1 连接。
- 固化插件机制是下一阶段 M1 的核心：M0 不需要完成自动加载，但不能以单一产品硬编码 Tool 结构封死 M1。

## 任务清单

### M0-T01 环境与依赖审计

- `git status --short`，记录 Node/pnpm/OS，检查已有仓库，确认需要重置的文件清单；不得未经授权删除用户文件。
- 查阅官方 `deepagents` TypeScript、`langchain`、`@langchain/core`、Zod 实际依赖和类型定义，安装兼容版本并锁定。
- 记录 Deep Agents `createDeepAgent` 的公开配置与本机实际类型；不根据历史聊天里的示例猜测 API。

### M0-T02 工程初始化

- pnpm Monorepo、TypeScript strict、ESLint、Prettier、Vitest、CI、`.env.example`、`.gitignore`。
- 先实现 `apps/agent-server` 与 `packages/agent-runtime` 两个有实际代码的最小包；构建与运行文档完整。
- 根命令 `pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm build`。

### M0-T03 原生 Agent + Tool 验证

- 使用官方 `createDeepAgent()` 和 LangChain `tool()`，让 Tool 实际返回模拟数据，不可只让模型背诵假结果。
- Tool 定义采用标准输入 Schema；将 Tool 逻辑集中在可替换工厂接口，避免绑定产品 A/B。
- 无模型凭证时 Mock 验证类型与执行路径，有凭证才执行真实模型端到端调用，标记哪些是 Mock。

### M0-T04 Deep Agents 运行扩展验证

- 验证 Skills 基于实际文件路径/Backend 配置加载；使用一个小的领域 `SKILL.md`。
- 验证一个只读 Subagent 的工具可见范围，防止无意继承所有高权限 Tool。
- 验证同 Thread 历史上下文与 Checkpointer；记录真实的 Runtime Context 传递接口。
- 采集 `messages`、`updates`、Subagent Streaming 的真实事件结构，保存去敏 Fixture。

### M0-T05 兼容性与测试报告

- 新建 `docs/deepagents-compatibility.md`：依赖版本、实际 API、运行命令、验证结果、局限性和 M1 对接要求。
- 建立 `docs/implementation-status.md`，只记录实际完成事项，不声明平台已经上线。
- 最小测试包括“Tool 确实被执行”“不同 Thread 不混淆”“敏感凭证不写入日志”。

## 允许修改范围

项目根配置、`apps/agent-server/`、`packages/agent-runtime/`、`skills/poc-*`、`tests/`、`docs/`；如确实需要可新增最小公共 Schema 模块，但不能提前实现 M1/M2 全套功能。

## 退出门禁

- 依赖安装可重现；TypeScript/测试/构建通过；有真实 Tool Call 证据。
- Skills、Subagent、Context、Checkpoint、Streaming 分别写出“已验证/未验证+证据”。
- 无法验证的官方能力必须记录阻断，不允许手写 Agent Loop 规避。
- 输出 M0 验收报告后**停止**，不自动执行 M1。
