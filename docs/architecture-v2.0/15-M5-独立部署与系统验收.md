# M5 · 同一套代码、双独立部署与 V1.0 MVP 完整验收（V2.0）

> 此阶段验证的是**企业产品复用能力**，不是 A/B 产品之间同步会话。两实例必须相互独立。

## 工作包

### M5-T01 两套独立部署

- A 实例只安装 `demo-product-a`、B 实例只安装 `demo-product-b`；两者使用相同版本的 Agent Server、Web 和公共契约。
- 分别配置模型、会话、Checkpointer、插件目录和业务 API；验证不共享凭证及会话数据。

### M5-T02 契约复用测试

- 选相同语义的测试数据，执行 `data_quality.get_trend@1` 与 `data_map.search_objects@1`，比较标准结构、口径、错误码、证据。
- 不允许主 Agent/ToolFactory 写产品身份判断；新安装 C 插件应可复用相同契约而不变更核心（可通过第 3 个模拟实现验证）。
- 能力缺失必须清楚 `UNSUPPORTED`；缺失数据报 `partial`/`insufficient`，不可伪造统计值。

### M5-T03 权限、页面、证据

- A/B 各做允许和拒绝的对象访问测试、敏感字段脱敏、Session 越权、引用二次鉴权。
- 嵌入模式询问“当前表”可正确获取不同宿主上下文；每个 Run 的 Snapshot 不受后续切页影响。
- 数据依据包含范围、统计时间、口径和来源；模型对原因推测明确区分验证状态。

### M5-T04 UI 与运行验收

- 独立 Web、React SDK、JS SDK、iframe 都能完成基本查询和证据展示。
- 模型/会话/插件管理仅查询当前实例；未授权用户无法操作模型配置。
- 校验取消、异常、工具超时、进程重启后的恢复策略，生成可观测性报告。

### M5-T05 质量门禁与交付

- 执行根 lint/typecheck/test/build、契约测试、安全测试、E2E；记录耗时、失败率、已知风险、未经实测项。
- 记录真实模型与 Mock 的差异；输出部署手册、插件开发样例、升级回滚步骤、M5 验收报告。

## 退出条件（全部必过）

1. 两个产品实例均独立可用，Agent 不感知产品身份。
2. **安装可信插件自动注册能力**，不需要修改 Agent 核心。
3. 同名能力契约一致，权限/脱敏由服务端保证。
4. 页面上下文准确、跨页面切换不污染运行。
5. 数据来源、范围、时间和口径能追溯，数据不足有明确限制。
6. 双 Web 模式、三种 SDK 路径正确；测试和安全报告可复现。
