# 16 · 测试策略、验收质量门禁与故障演练

## 1. 测试分层

| 类别             | 工具建议                          | 最低覆盖                                              |
| ---------------- | --------------------------------- | ----------------------------------------------------- |
| Unit             | Vitest                            | Catalog、Schema、Result、Normalizer、Plugin Validator |
| Contract         | Vitest + JSON fixtures            | A/B 标准输入输出等价、错误码、版本兼容                |
| Integration      | HTTP test client + Mock server/DB | Loader→Registry→Tool→Agent、API/Checkpoint/SSE        |
| Security         | 专项自动化                        | 权限绕过、凭证泄漏、插件路径穿越、iframe Origin       |
| E2E              | Playwright                        | 独立 Web、React SDK、Vanilla、iframe 完整问答         |
| Model Evaluation | 离线固定数据/人工复核             | 证据引用、无依据结论、工具选择可靠性                  |
| Load/Resilience  | 轻量压测与故障注入                | SSE 恢复、超时、上游 5xx/429、模型故障                |

## 2. 关键契约测试矩阵

| 编号 | 输入/场景                   | 预期                                    |
| ---- | --------------------------- | --------------------------------------- |
| CT01 | A/B 同标准质量趋势          | 符合相同 Schema/单位/口径，数据意义一致 |
| CT02 | B 不支持日聚合              | `partial/UNSUPPORTED`，不得补造数据     |
| CT03 | 输入日期非法/范围太大       | `INVALID_INPUT`，Tool 不调用上游        |
| CT04 | 上游字段命名变化            | `SCHEMA_MISMATCH`，审计可追溯           |
| CT05 | 两插件重复提供同能力同版本  | 明确冲突或显式选 Provider，不能随机覆盖 |
| CT06 | 插件 entry 指向目录外       | 加载拒绝                                |
| CT07 | 未安装能力                  | 不出现在 Agent Tools                    |
| CT08 | Agent 无工具权限            | Tool 强制拒绝，不以模型可见列表代替授权 |
| CT09 | 缺失 Evidence               | 视契约返回警告或不合格，不伪造引用      |
| CT10 | 旧 run 期间当前页面切换对象 | 旧 Run 继续用旧 ContextSnapshot         |

## 3. Auth / Isolation / Privacy

- 用户 A 复制用户 B 的 Session/Run/Context/Evidence/Thread ID；必须 403/404，不泄漏存在与否敏感细节。
- 原业务 API 返回 PII 但用户无权访问；Filter/Adapter/业务 API 共同阻止暴露到模型及客户端。
- 管理员 API 不因用户手动请求 URL 或设置 `role=admin` 即可访问。
- Secrets 不在 HTTP 响应、日志、SSE、前端 Bundle、插件 Manifest 中出现。
- RunEvents 幂等、序号单调、不同 Run 隔离。

## 4. Model Evaluation 用例

准备含明确答案的模拟样例：正常数据、缺失三天、反向趋势、不同统计时区、无足够因果证据、相似但不同的指标口径。人工和程序验证：

- 工具是否真的被调用（Trace/Mock Call Count）。
- 回答引用的证据 ID 是否真实存在并属于本次授权范围。
- 模型在数据不足时是否明确“不足以判断”；不能把推测说成已证实。
- 复杂任务是否在 Subagent 有权限时才委派；不能越权调用隐藏工具。

## 5. 流式协议故障测试

- 断流重连、重复事件、丢失事件、取消 Run、网络抖动、服务重启/事件游标过期。
- 消息/工具事件顺序与 UI 状态一致；重放 event 不生成重复消息。
- Thread 恢复后权限仍重新校验；历史来自旧授权不意味着现在仍有权重新查询对象。

## 6. CI 阶段门禁

1. M0：安装/类型检查/单测/构建；SDK 兼容性 Fixture。
2. M1：增加 Plugin Manifest/路径安全/契约/Local/HTTP 驱动测试。
3. M2：增加 Session+Checkpoint/API/Policy/Audit/SSE 集成测试。
4. M3：增加 UI 的 chat/admin E2E、数据不足与引用。
5. M4：增加三宿主集成、iframe Origin、style isolation、unmount。
6. M5：增加 A/B 独立部署、系统安全/回归/故障演练。

阶段可以记录未完成非阻断优化，但不能将 P0 阻断项标记为“通过”。
