# 17 · Codex 分阶段执行手册（架构基线 V2.0）

## 1. 执行目的

根据**新版业务优先架构**从 M0 重新实施；M0/M1 以 SDK 验证和插件自动挂载为基础，M2/M4 以**权限继承、上下文感知和证据追溯**为验收核心。不要向通用 OpenClaw 方向泛化。

## 2. 首次执行准备

1. 将此包解压到仓库 `docs/architecture-v2.0/`；将 `AGENTS.md` 放在仓库根。若已有根 AGENTS，先合并并审查冲突。
2. 若原仓库有旧 M0 代码，**可以重做 M0，但必须先 `git status`，明确重置范围，不能未授权删除用户文件或历史记录**。
3. 不再引用旧 `docs/architecture-v1.0/` 的命令或验收结果；必要时保留旧目录为归档，不让 Codex 混用。
4. 初始化阶段采用独立工作分支，生成 `docs/implementation-status.md` 记录实际进度。
5. 安装官方 Deep Agents 时，以实际安装包版本类型和官方文档核对，不套用旧版聊天中的 API 名称。

## 3. 阶段路径

```text
M0: Deep Agents 原生 SDK 验证 + 最小工程
 ↓
M1: Plugin SDK / Loader + 标准 Capability + 两套适配器
 ↓
M2: 身份/Policy/Context/Evidence + Session + SSE
 ↓
M3: React + Ant Design X Chat Core / 独立 Web
 ↓
M4: React/JS/iframe 嵌入，页面上下文感知
 ↓
M5: A/B 独立部署，契约/权限/证据总验收
```

## 5. 阶段回合要求

每次只执行单个 Mx 阶段。按编号逐一完成任务，不大规模生成空壳；阶段完成后提交完整验收报告并停止。只有收到明确“继续 Mx+1”才进入下一阶段。

## 6. 特殊处理

| 情况                      | 处理                                                       |
| ------------------------- | ---------------------------------------------------------- |
| 官方 SDK 新参数与示例不符 | 以当前安装版本为准，写最小复现和兼容性报告；不伪造 API     |
| 缺少模型密钥              | 使用 TestDouble 验证逻辑，真实模型验证记 Not Run           |
| 缺少真实业务平台          | 双模拟 Adapter 进行契约测试，不能宣称真实权限集成已完成    |
| 当前仓库已有 M0           | 使用新版逐项重新验收；保留可复用代码，冲突处明确重构理由   |
| 插件安装失败              | 停止装配有问题的插件，显示诊断，不静默继续把能力暴露给模型 |
| 框架能力不兼容            | 写 Blocking Issue/ADR，未经批准不能重写 Harness            |
| 新增功能与业务定位无关    | 暂缓，优先完成标准契约、权限、Context、Evidence 与插件     |

## 8. 稳定的扩展原则

- **新增产品**：实现并安装标准 Adapter 插件，Agent 不改。
- **新增业务 Capability**：先建立契约与测试，再由插件实现、自动挂载。
- **新增领域 Skills/Subagent**：明确专业职责和工具权限，使用 Deep Agents 官方装配点。
- **新增 Web 呈现**：遵循标准 ViewModel + Shared Chat Renderer，不允许后端下发可执行 UI 代码。
